## Scheduler

Reuse `dynamic_outbox` instead of adding an independent worker/lease subsystem. MongoDB stores one cursor per tenant/project/schema/workflow and one outbox root event per nominal UTC occurrence. Cursor advancement and event creation commit together in a transaction. Unique occurrence identity includes scope and scheduled instant, independently of worker/replica. The root captures the workflow definition; current source metadata still supplies access policy and the active workflow must still exist before execution. Database changes, child outbox events, and root execution marker commit together. External side effects retain the existing child outbox/provider idempotency contract; this is not an exactly-once external network guarantee.

On first discovery or definition/schedule change, initialize the next tick after discovery; do not run historical schedules that were never registered. Persisted cursors survive restarts. Recover due instants from the preceding 24 hours, at most 100 per workflow and 500 total per poll; rotate the first workflow for fairness. Older instants advance to the recovery horizon with an explicit skipped-before timestamp. UTC and configured timezones/DST use the existing cron parser, and `@every` remains anchored to the Unix epoch. An unchanged reload never resets a cursor. Disabled/removed workflows do not create new jobs or execute pending roots. A metadata reload error retains schedules but queued execution still checks current source existence/activation. A canceled scheduler cannot advance a cursor without its durable event.

Use the existing bounded outbox retry/backoff, exhausted-job status, lease renewal, and owned acknowledgement. Queue root execution has a 50-second transaction cap below MongoDB's default transaction lifetime, covered by a 90-second lease reserved before dispatch; do not heartbeat-write the claim during the transaction. Cron roots for one workflow are serialized with a MongoDB execution fence in their transaction; a duplicate/reclaimed root observes its committed marker. Root commits require a live outbox claim so an expired/stolen attempt cannot commit. Do not hold network effects inside these root transactions: validation already requires outbox execution for effectful steps. Terminal outbox failures remain visible for operator repair; retries are not infinite.

Legacy refresh sessions expire/re-login naturally; no mass deletion is required. Real production verification/deployment remains pending until server or GitHub access exists.

## Alternatives considered

A separate cron worker would duplicate the outbox's claim, retry and observability code. Redis attempt markers cannot provide crash recovery. Reusing MongoDB cursors and the outbox gives one durable delivery mechanism with real transaction tests.
